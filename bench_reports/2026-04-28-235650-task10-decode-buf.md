### Key observations

3. **Wall clock improved by 1.3% vs Task9** (11.609s -> 11.459s by perf stat): The improvement is modest but consistent with the reduced allocator pressure. The direct allocator cost of ~780K fewer malloc/free pairs is small in absolute time; the larger benefit is reduced cache pressure from fewer heap fragmentation events.

4. **Page faults reduced 4.4% vs Task9** (158,784 -> 151,836): Fewer heap allocations mean fewer virtual memory pages need to be faulted in. The `decode_buf` reuse keeps the same physical pages warm across calls, contributing to this improvement.

5. **Peak heap unchanged** (451.46 MB vs 451.46 MB): As expected — `decode_buf` is a bounded buffer (capacity grows to max block size and stays there), not a persistent accumulator. It does not increase peak memory.

6. **Uncompressed path now copies into decode_buf**: To resolve the borrow checker lifetime conflict (returning `&'a [u8]` that can only come from one `&'a mut Vec<u8>`), the uncompressed path does `decode_buf.extend_from_slice(block)` instead of returning a direct slice of `read_buf`. This adds a small extra copy for uncompressed blocks, but uncompressed bigWig data is extremely rare in practice (all files in this benchmark are zlib-compressed, as indicated by the `0x78` magic byte check being taken on every call).
