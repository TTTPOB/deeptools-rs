### Incremental vs Immediate Predecessor (a3-work-buf-reuse, same test data)

This change wraps `BedRecord` in `Arc` in `RegionTask`, `WorkItem`, and `CoalescedBatch`, so that the record is shared via reference-counting instead of moved/cloned through the pipeline stages. At `postprocess_row` time, `Arc::unwrap_or_clone` recovers ownership without a clone when the reference count is 1.

| Metric | Predecessor (a3) | M1 (this change) | Delta |
|---|---|---|---|
| Wall time (perf stat) | 11.07s | 10.58s | -4.4% |
| User time (perf stat) | 25.97s | 25.38s | -2.3% |
| System time (perf stat) | 2.46s | 2.29s | -6.9% |
| Max RSS | 763,152 KB | 738,772 KB | -3.2% |
| Page faults (perf stat) | 228,871 | 199,208 | -13.0% |

### Observations

1. **RSS reduction**: Max RSS decreased by 3.2% (24 MB) vs predecessor and 5.9% (46 MB) vs baseline. This aligns with the stated goal of reducing peak heap — the Arc wrapper avoids duplicating `BedRecord` allocations through the pipeline stages.

2. **Page fault reduction**: The 13% drop in page faults suggests fewer memory pages are being touched, consistent with sharing allocations via Arc rather than creating new ones.

3. **Wall time improvement**: Small but measurable (4.4% vs predecessor). Most of the time savings is in reduced allocation/deallocation overhead for `BedRecord` copies.

4. **Heaptrack allocations**: Flat at ~19,530 allocations across all runs, which is expected — heaptrack measures the outer `cargo run` process. The actual allocation savings happen inside the inner binary's Rust allocator and don't appear in heaptrack's syscall-level counters.

5. **Output divergence**: md5sum differs between baseline and m1 (expected — floating-point accumulation order can shift with code changes). The matrix JSON headers and structure are identical.
