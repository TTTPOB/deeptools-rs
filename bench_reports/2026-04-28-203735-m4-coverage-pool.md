### What changed

1. **Wall clock -23.9% (15.13s to 11.51s):** Better CPU utilization (226% to 303%) from the channel pipeline (T10) keeping all 4 cores busy during I/O wait. Coalesced reads in baseline hid some I/O cost behind sequential batches; the parallel channel architecture more than compensates despite no-coalesce mode.

2. **Max RSS -34.3% (784 MB to 515 MB):** Three stacked allocation reductions: (a) shared pread-based readers (T4/T7) avoid per-thread mmap mappings, (b) channel streaming (T10) eliminates buffering all results in memory, (c) thread_local coverage buffer pool (T11) reuses Vec<Vec<f32>> across process_batch calls.

3. **Page faults -28 to -40%:** Fewer allocations overall from Arc<BedRecord> sharing (T8), thread_local work_buf reuse (T7), and the coverage buffer pool (T11). The 142K page faults in the final run are dominated by the kernel page cache for bigWig file data, not heap allocations.

4. **Voluntary CS +663%:** The sync_channel in T10 introduces thread coordination that did not exist in the baseline sequential pipeline. Each batch result triggers a channel send + BTreeMap insert on the writer thread.

5. **User time +6.9% (27.18 to 29.05):** The "no-coalesce" strategy processes 269,800 individual items (vs 117,083 coalesced batches in baseline), each requiring a per-sample bigWig read + bin extraction. The extra I/O and dispatch overhead is visible in user time, but the parallelism gain in wall clock still wins overall.

6. **Heaptrack allocations unchanged (~19,531):** Heaptrack measures the cargo build process including compilation, not just the application runtime. The application-level allocation reduction from the buffer pool is dwarfed by build-time allocations in heaptrack's view.
