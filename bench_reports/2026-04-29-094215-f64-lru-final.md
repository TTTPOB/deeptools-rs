### 5. Remaining regression source: voluntary context switches

Vol ctx switches rose from 286 (baseline) to 8,691 (LRU f64). The baseline used DashMap
(lock-free sharded), while quick_cache uses parking_lot locks. Under 4 rayon threads, LRU
eviction creates lock contention during insert-with-evict paths. This contributes ~0.8s of
system time overhead. Potential mitigation: increase cache capacity to reduce eviction
frequency, or use a lock-free concurrent cache.

| Peak heap +74% (785 MB vs 451 MB) | ~0.3s | More page faults (+51%), TLB misses |
| quick_cache lock contention | ~0.3s | 8,691 vol ctx switches vs 286 baseline |
| Slightly higher zlib % (46.2% vs 43.3%) | ~0.2s | LRU cache warm-up + eviction overhead |

### 7. Verdict

**PASS** — regression within expected bounds for f64 memory width doubling.

Wall clock +11.4%, task-clock +14.8%. The ~12% regression is consistent with the 2× buffer
width and +74% peak heap increase. The CPU profile proportions match baseline, confirming no
algorithmic regression. The DashMap cache thrashing bug is fixed.
